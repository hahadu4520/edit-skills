# 像素风剪辑

把一条真人口播视频剪成“真人 + 像素小世界”的风格：讲概念时切进星露谷式的像素场景，讲操作时换成像素风的 Agent 软件界面，真人一直在旁边陪着讲。

样板片是 hahadu 的《Git 和 GitHub 到底是什么》（3:4，4 分 46 秒，另有 16:9 横版）。`scripts/` 里的代码就是这条片子的完整剪辑工程：时间表、镜头、卡片、字幕都是这期的内容。新片照着它复制一份，**只改内容和时间表**，画法和动效直接复用。

## 用户的工作习惯（必须遵守）
- 用户自己做粗剪、降噪、美颜，原片通常已经烧录字幕。不要重做这些，只按剪辑策划加画面。
- **每一步先出 1–3 张关键帧给用户看，用户说 OK 再做动效和渲染。** 不要一上来就渲染整片。镜头表、关键帧、开头约 1 分钟小样、全片，逐级确认。
- 要精致、干净。新画面的风格和精细程度必须和现有 B-roll 一致，不能一眼看出是另一套画法。
- 不画电脑、显示器、键盘。要表现软件里的操作，就直接画软件界面本身。对话框里的 AI 统一叫 “Agent”，画面里不出现具体产品名（比如 “Claude Code”）。

## 主角：换成你自己的形象
- 样板里代表博主的主角是 hahadu 频道 logo 的棕色像素小熊（`assets.py` 的 `BEAR` 16×24 走路全身像、`BEAR_PORT` 32×32 对话框头像、`BEAR_PAL` 配色；`examples/bear-*.txt` 是像素稿）。**这是 hahadu 的频道形象，请换成你自己的**：照同样尺寸画一个，替换 `BEAR` / `BEAR_PORT` / `BEAR_PAL` 即可，`person()`、`dialog()` 会自动用新形象。
- 名牌和样板文案里的 “du” 换成你的名字（`acards.py`、`bscenes.py`、`ccards.py`、`pcards.py` 里搜 `du`）。
- Agent 的形象是另一个角色：橙色像素小怪（`acards.py` 的 `MASCOT`），当 logo 和 C 段左下角的小助手，可以照用。

## 镜头类型
- **A 真人**：原画，必要时叠像素小装饰：开场标题、问号气泡、目录 chips、“第1招/第2招” badge、RPG 三选一菜单、结尾关注按钮（`overlays.py`、`overlays2.py`）。只在需要强调的地方用 1.06–1.08 的缓推。
- **B 像素 B-roll**：全屏 HD-2D 像素场景，把概念讲成星露谷式小世界：草地、小路、树、房子、像素小人、存档软盘、V1–V4 木牌、分支小路、云端岛、栅栏和锁（`world.py`、`assets.py`、`bscenes.py`、`k4_anim.py`）。上方是木框标题卡（橙色标签 + 小标题），下方是 RPG 对话框（主角头像 + 名牌），台词和口播一致。
- **C Agent 界面**：替代录屏。草地背景上叠 B 段同款像素 UI（`acards.py` 里的 UI kit，`ccards.py` 里是卡片内容和时间表）：
  - 标题栏：小人 logo + 项目名 + 一句标题。
  - `you` / `agent` 对话框：带头像和名牌（用户 / 朋友 / Agent）。
  - 紫色 “对 Agent 说” 输入框：大号 2× 像素字逐字打出，有光标和“发送”按钮。
  - 终端块、链接条、打勾清单（可以逐条出现）、进度条。
  - 存档栏（软盘图标）、设置/连接器列表（右侧按钮）、diff 代码块、像素网页预览、toast 提示。
  - 整个窗口堆叠**贴底**，正好在小助手和头像那一排上方（BOTTOM=212）。字少时是上方露出草地，中间不留空。
  - 左下角是像素小助手（橙色小怪），站在小路上，有气泡台词，idle 时轻微上下浮动，happy 时蹦跳加闪光。台词跟着每张卡变化（“等你输入…”“搞定！”）。
  - 右下角是用户的圆形人像小窗：r=340，位置 (700,860)，5px 白边加柔和投影，从原片 (60,110,1020,1070) 裁脸。
- **C' 真实对话截图**：Agent 对话类的镜头（用户提问 + Agent 回复 + 命令结果）可以用清晰的软件对话截图代替像素界面，两种可以在一条片里穿插使用。
  - 截图是用 HTML 排出一个通用的聊天软件界面（`screenshots/chat.css` + 每张卡一个 html），再用 Playwright 以 2× 截图（竖版用 `shoot2.js` / `shoot3.js`，横版用 3× 的 `*-dsf3.js`）。界面包括：顶栏（小怪 logo + 项目名）、用户气泡、Agent 回复、深色“运行命令”块、链接条和底部输入框。界面上不出现 Claude Code 字样。
  - 我们对话里真实出现过的内容，直接用原话；没出现过的，编一段合理的对话。
  - 要高亮的词用 `<mark data-k=1>` / `<mark data-k=2>` 标出来。`shoot3.js` 截三版：无高亮、第 1 组亮、两组都亮，同时记下 mark 的位置。`ccards.shot_img` 在口播对应的时间点，从左往右把高亮版扫进来。这样深色终端里的高亮也正确。
  - `acards.shot_scene` 把截图按全分辨率（宽 1000px）贴进 B 段同款木框，木框贴底，小助手和人像小窗那一排不变。截图高度要控制在 CSS 约 380px 以内，否则放不下。
- **S 总结卡**：像素清单卡，也带圆形小窗。

## 技术规格
- 低分辨率画布 270×360，最近邻 ×4 放大到 1080×1440。字体用 Fusion Pixel 12px，没有 ✓ 字形，打勾手画。
- HD-2D 调色（`banim.py` 的 BAnim）：world 层做暖色 golden 调色，加光束、bloom、移轴模糊、暗角和漂浮粒子。UI 层不调色，保持锐利。调色结果按 world 图 md5 缓存（缓存上限 8，避免爆内存）。
- 动效元件：`pop_into` / `pop_world` 是 ease-out-back 弹出，`typed()` 打字机，`burst()` 星星爆点，人物走路时上下抖 1px。荧光笔高亮从左往右扫 0.28s，颜色 (255,226,72)，被高亮的文字变深色。
- 关键词高亮标记：`[x]` 是第 1 组，`〔x〕` 是第 2 组，各自对应口播里的时间点。
- 字幕：A 段用原片烧录的字幕。B/C/S 段盖住了原字幕，要重打：思源黑体 Heavy 54px，白字加 7px 黑描边，中心 y=1272（`subs.py`）。字幕时间从原片烧录字幕区域的变化检测出来（原片没有烧录字幕时，用 `transcribe.py` 转写），文字逐条核对，专有名词要写对（比如 GitHub）。
- 转场：
  - 进出 B：24px 网格像素溶解，马赛克加随机方块，0.3s。
  - C 首卡：在压暗 45% 的上一帧上 pop-in 0.35s，小窗从右侧滑入。
  - C 内换卡：UI 淡入并上移 10px，0.22s。
- 音效：numpy 合成 8-bit 方波/三角波（弹出、打字、高亮、存档、成功），-24 dB 压在人声下面（`sfx_full.py`）。
- 转写：sherpa-onnx SenseVoice（从 GitHub releases 下载模型）加 silero VAD（`transcribe.py`）。
- 渲染：`render_full.py OUT T0 T1`，分 4 段并行渲染，再 concat，配混好的 s16 音轨（48k 立体声），AAC 192k，+faststart。

## 流程（3:4 竖版）
1. **策划**：读用户的文案和原片，把每句口播归到 A / B / C 三种画面，写成镜头表给用户确认。规则：B 不连着超过 2 个，每个 4–8 秒；真人不连续超过约 12 秒；A / B / C 大约各占三分之一。
2. **转写和字幕时间**：`transcribe.py` 转写（SenseVoice + silero VAD），或从原片烧录字幕区域检测时间；定 A/B/C 时间表（`render_full.py` 里的 `SEG`）。
3. **关键帧**：B-roll 和 C 卡各先出 1–3 张关键帧，贴上真实小窗和字幕给用户看，等确认。
4. **补齐动效**：确认后补齐所有镜头，把动效时间点对齐口播：高亮、打字、弹出、小助手反应。
5. **渲染**：先渲染 3 秒左右的测试片段抽帧检查；再用 `render_full.py OUT.mp4 T0 T1` 分 4 段并行渲染整片，concat 后混入 `sfx_full.py` 生成的音效轨。先给开头约 1 分钟的小样，确认后出全片。

## 横版 16:9（竖版定稿后再做）
时间线、剪辑点和音频直接沿用竖版，不重剪人。用 `scripts/r16.py`（和竖版脚本放同一目录）：
- 画布是 480×270 像素网格（×4 = 1920×1080）。
- **A 真人**：左边大像素看板（竖版叠在脸上的标题、目录、第1招/第2招等全部搬到看板上，内容放大 6 倍）；右边是**无框** 3:4 人像小卡（原片裁 x 135–945、y 0–1080，20px 圆角 + 很淡的绿色阴影，不要木框、不要白框），下边缘和看板对齐。一帧只强调一个重点（人或看板）。
- **C 界面**：卡片放大 3–5 倍放左边，信息要大到一眼能读；对话截图用 3× 重拍（`screenshots/shoot2-dsf3.js`、`shoot3-dsf3.js`），去掉标题栏放大到约 1200px 宽；人像同款小卡放右上，A↔C 之间小卡滑动缩放 0.35 秒。
- **B 像素**：竖版场景整块放中间，两侧补草地、树和延伸的小路；标题卡挪到左上，对话框挪到右上，底部只留字幕。
- **字幕**：中英双语，中文思源黑体 Heavy 50px 在上，英文 Inter SemiBold 34px 在下，都是白字黑描边。时间轴写在 `cues_bi.json`（`[开始, 结束, 中文, 英文]`）。**先交中英对照表给用户审，再烧进画面。**
- 渲染：`SRC=原片.mov bash scripts/render_parts.sh 0 总时长 4 输出目录`，4 段并行再 concat，然后混入竖版成片的音轨。约 8–10 分钟。

## 封面
- **3:4 竖版封面**（`scripts/cover34.py`）：用用户从视频里截的一帧，**原字幕保留**，只在人物一侧的空处加 3 行得意黑短句。
  - 一种字体、一种字色、一种字号，深色字 + 白描边 + 轻阴影（去掉描边会太淡）。不要便签、贴纸、多种颜色，不要两边都写满，小字里不再分重点。
  - 位置在嘴巴到肩膀之间的高度（不要压在脸的上方），行距稍宽，不要碰到头发。
  - 文案讲“谁看 / 为什么看 / 看完能干啥”，每行一个短语，不要一整句话，也不要全是功能描述。样板：`0 基础也能懂 | Vibe Coding 必备 | 存档·协作·上线`。
  - 用户确认过的文案，改样式时不要顺手改。
- **横版封面**（`scripts/cover_wide.py`）：从 16:9 成片重新导出开场帧（不要用屏幕截图，免得带进桌面杂物），出 YouTube 16:9（1280×720）、B 站 16:10（1920×1200）和 B 站首页 4:3（1440×1080）。比例不够的地方用同一套像素草地在上下补出来，不裁内容。

## B-roll 怎么不重样（做第二条以后）
- **固定**（观众认出你的部分）：像素密度、HD-2D 光效、字体、主角、小怪助手、标题卡、对话框、像素溶解转场。
- **每期换一套**：场景地图（这期是星露谷草地，下期可以是港口、太空站、列车、图书馆）、季节和配色、天气粒子、镜头视角。
- **每个镜头新想**：具体比喻和道具，同一个道具不跨期反复当主角。
- 真正复用的是“动作套路”：保存一个状态 / 从 A 搬到 B / 一串版本再回退 / 分叉再合并 / 两方撞车 / 申请→审批→生效。同一个套路一期最多用 2 次，两次换不同视角。
