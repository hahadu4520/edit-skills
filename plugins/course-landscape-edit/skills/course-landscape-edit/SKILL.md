# 横版课程剪辑（课程横版风格）

样板：豆包电商第 1 集 v6（8 分 34 秒）。

本文件分两种约束，要分清：

- **定死的（照做，不重新设计）**：画面骨架和尺寸、配色、字体、字幕、进度条、PPT 样式、时间轴结构，以及每节里写明的「不要做的」。目的是每一集看起来是同一个系列。
- **底线，不是上限（鼓励做得更好）**：动效、转场、镜头运动。本文件写的是第 1 集做到的水平，后面每一集都可以在同一风格下做得更好，见第四节。

标「待定」的还没跟 du 确认过，要先做小样给 du 看。

## 第 0 步：先自检依赖（每次开始剪辑前都做）

运行 `bash <SKILL>/check.sh`（Windows：`powershell -ExecutionPolicy Bypass -File <SKILL>\check.ps1`），`<SKILL>` 是本文件所在目录。
- 输出 OK：直接开始。
- 缺东西：**不要只告诉用户缺依赖，也不要让用户自己去装**。直接运行 `bash <SKILL>/install.sh`（Windows：`install.ps1`）把缺的全部装好，装完再跑一次 check 确认。安装要 5–15 分钟，开始前跟用户说一声“第一次用，先帮你装好依赖，大约 10 分钟”。

然后 `bash <SKILL>/new_project.sh <工作目录>` 建一期新工程：原片放 `<工作目录>/src.mp4`，素材放 `<工作目录>/素材/`，所有脚本在 `<工作目录>/ed/` 里跑，Python 用 `ed/venv/bin/python`。

## 工程里有什么（scripts/ → 新工程的 ed/）

| 文件 | 作用 |
|---|---|
| `compose.py` | 合成器：`python compose.py out.mp4 T0 T1`，读 segs/clips/chap/subs/en，画整帧并编码。T1-T0 取 0.034 就是出单张关键帧 |
| `build_cut.py` | 口播粗剪：按保留区间拼 src_cut.mp4（12ms 淡化），重映射字幕时间。保留区间和旧时间轴是第 1 集的，新片要改 |
| `clips.py` | 从录屏里抽帧到 `rec/` 并写 clips.json（素材目录用环境变量 `MAT`，默认 `../素材/`） |
| `slides/*.html` + `shot_slides.js` | 第六节的全部页型。`node shot_slides.js slides slides/out <页名...>` 截成 jpg |
| `anim/D1–D7.html` + `lib.js` + `ra.js` | 第三节的动效卡。`node ra.js $PWD/anim D7 <秒数>` 渲染到 `anim/fr_D7/` |
| `cmpfull/*.html` + `rl.js` | 开场对比的全屏底图。`node rl.js $PWD/cmpfull` 出透明 png |
| `kf/gen_bar.py` | 读 `chap.json`（时间）和 `chap_names.json`（章节名），生成进度条章节名图层：`cd kf && python gen_bar.py && node ../rl.js $PWD` 出 `kf/lab_i.png` |
| `kf/gen_scenes.py`、`kf/scenes/` | 标题卡（scene）模板 |

`<SKILL>/examples/` 里是第 1 集的 segs/clips/chap/subs/en 和 6 张成片截图（每种主要版式一张），写新时间轴前先看一遍。这些文件都是第 1 集的内容，新片只照着结构改内容，不要原样用。

## 一、画面骨架（1920×1080，30fps）【定死】

全片只有两种画面：

1. **开场对比**：全屏，没有人像。
2. **分屏**：其余全部是这种，只有两块，不加第三块。

| 元素 | 参数 |
|---|---|
| 画布底色 | #F4F2EE，两块都带柔和投影（高斯 20，不透明度 0.13，向下偏 18px） |
| 左内容区 | x48 y112，1360×765（16:9），圆角 28 |
| 右人像框 | 432×520，x=1440，底边和左内容区对齐（y=357），圆角 26，比内容区矮一截 |
| 人像取景 | 原片 1440×1080 中取宽 897 的竖条，居中 x=152，缩到 432×520。脸约占框宽一半，头顶留白，露肩和手 |
| 字幕中心 | y = (112+765+1080)/2 ≈ 980，在内容区下方的空白里 |
| 进度条 | 画面最上方，见第五节 |

不要做的：

- 纯人像全屏；
- 人像框做宽；
- 人像镜头上加花字；
- 每个画面都挂 logo（logo 只在 PPT 上）。

## 二、时间轴（课程结构）【定死】

按这个顺序排。章节名就是进度条上的名字，按内容改词，但结构不变。

| 段落 | 进度条章节 | 左侧放什么 |
|---|---|---|
| 0–约 26s | 效果展示 | 开场对比 × 3 组（原爆款 vs 生成），放完淡入「一键完成」卡 |
| 紧接 | 效果展示 | 标题卡：「以上全部用 X 一键完成」+ 三张成品截帧小卡 |
| | 效果展示 | 动效卡：「不需要 ✕✕✕，只需要一个 X」；标题卡：「为什么要用好 X」+ 能力 chips；动效卡：能力拼图 → 一站式 |
| | 效果展示 | 课件：封面 → 目录（agenda） |
| 第一部分 | 上手 X | 章节页 d1 → 界面介绍截图（快推 + 定住） |
| 第二部分 | 每一步一个章节 | 章节页 d2，然后每一步都是两拍：① 提示词课件页（可暂停照抄）② 对应录屏 |
| 收尾 | 回顾 | 回顾课件（四步）→ 延伸动效卡 → 回顾课件 → 下集预告 |

时间轴规则：

- **每句口播左侧都要有内容。** 原来是纯人像的句子，就配成品视频、标题卡、提前切到下一页课件，或者新做一张卡。
- **左侧换画面的时间点卡在字幕句首。**
- **章节起点跟着内容走。** 某段画面借用了下一章的时间，章节起点也要跟着挪，不能出现「画面还在表格、进度条已经跳到回顾」。
- **讲到操作结果时给足镜头。** 比如「连上飞书后输入什么」，先给输入的提示词约 7s（打完后停住让人看清），再给 AI 结果约 6s，再给打开的结果页约 7s。时间不够就从后面的回顾页借。

## 三、左内容区的版式库（按文案类型选，可以新增）

| 版式 | 长什么样 | 适合的文案 |
|---|---|---|
| **开场对比**（全屏） | 两条竖版视频各 432×768，并排居中（x=468 / 1020，y=112），圆角 24。中间蓝色圆形箭头。两侧外边各一个标签：左「原爆款」灰底，右「豆包工作生成」蓝底。只挑两边镜头结构一致的片段 | 效果展示、前后对比、原片 vs 生成 |
| **课件页**（slide） | 见第六节 PPT 样式 | 提示词、步骤说明、目录、回顾、章节页、封面、预告 |
| **标题卡**（scene） | 白底，左上一行灰色小引语（34px），下面一句 72–84px 黑色超粗标题，关键词套蓝色圆角块。下方三选一：三张成品截帧小卡（200×300，右上蓝色 ✓）；或一排蓝色 chips；或两张对比卡（灰底，小字类别 + 大字结论） | 一句话结论、金句、「为什么」、额外提醒 |
| **动效卡·否定清单**（D1） | 一条条「✕ xxx」逐条出现，再划掉，最后「只需要一个 X」+ 步骤词 | 「我不需要 A、B、C」 |
| **动效卡·能力拼图**（D2） | 几个能力块依次弹出，汇成「一站式」 | 列举功能后收束成一个卖点 |
| **动效卡·分类对比**（D3） | 左右两类（如卡点类 / 口播类）各配一个侧重点，下面给例句 | 「如果是 A 就……，如果是 B 就……」 |
| **动效卡·关键词放大**（D4） | 灰色小引语 + 两个 150px 大词（第二个蓝色）+ 一排流程 chips（v1 → v2 → 定稿 ✓） | 方法论口号、「多审核多校准」 |
| **动效卡·技巧卡**（D5） | 「错误写法」引号句 vs 「正确做法」，标「小技巧」 | 技巧、省钱省额度 |
| **动效卡·数据闭环**（D6） | 系统 ⇄ 平台箭头，表格行逐条出现，带 +182% 放大 / -30% 淘汰 标签 | 后续玩法、数据回流、放大淘汰 |
| **动效卡·对话示范**（D7） | 仿聊天框：顶部「不满意？直接用 **大白话** 说哪里要改」；用户蓝色气泡逐字打出，每秒 22 字；最后 AI 灰色气泡回一句确认；底部是输入框 | 「用大白话说就能改」这类讲交互的句子。录屏里没有合适画面时用它 |
| **录屏**（rec / clips） | 原尺寸录屏按取景框裁切，镜头规则见第四节 | 所有实际操作 |
| **成品展示**（vid） | 竖版视频居中（高 = 765-60），背景是同一帧放大、模糊 40、压暗到 55% | 「看到一条视频的效果了」 |
| **素材占位** | 对应课件页 + 左上角红底白字标签「Rx 待补：xxx」 | 缺素材时继续往下剪；交付版里不能留 |

选版式的优先级：有真实录屏或成品就用真实的；没有再用动效卡；动效卡也不合适就用标题卡。

上面没有合适的版式时，可以设计新版式。新版式要在左内容区里、用同一套配色和字体。先做小样给 du 看，认可后加进这张表。

## 四、动效和转场【底线，不是上限】

这一节是第 1 集的起点，不是天花板。只要守住「风格边界」和「硬性不要」，动效和转场都应该比上一集做得更好。

### 运镜和转场清单【代码强制】

术语：**运镜**指画面里的镜头运动，传统说法「推、拉、摇、移、跟、升降」；我们对录屏、截图做的是后期运镜（数码推拉）。**转场**指两个镜头之间怎么接。

`scripts/rules.py` 在每次合成前自动检查 segs.json / clips.json，违规直接报错、不出片。也可以单独跑 `python rules.py` 先查。

| 类别 | 允许 | 待试（先做小样给 du 看，认可后在 compose.py 实现并写进 rules.py） | 禁止 |
|---|---|---|---|
| 运镜 | 固定；快推定格（punch-in）：取景框每次变化在 0.8s 内完成，之后画面完全不动 | — | Ken Burns（缓慢推拉、缓慢平移）；clips 里起止框同宽不同位置（会整段慢移） |
| 转场 | `dissolve` 叠化 0.3s（默认）；`cut` 硬切 | `slide` 推入/滑入；`match` 匹配剪辑/元素转场 | 闪白、旋转、翻页 |

segs.json 每段可写 `"trans"`，表示从上一段切进这一段的方式，不写就是叠化。新增运镜或转场：先做小样 → du 认可 → 实现 → 加进 rules.py 的允许清单。

### 风格边界（不变）

- 调性：浅色、简洁、轻、干净，和米白画布、蓝色主色一致。
- 动效服务于讲解：每个动作都对应口播里的一个词或一句话，卡在字幕句首出现。具体做法是把那几句字幕时间减去段落起点，写进 HTML 的时间数组 C。
- 动效发生在左内容区里。人像框和进度条位置不动，是画面的锚点。

### 硬性不要（du 明确说过）

- 缓慢推近、缓慢平移的镜头：du 认为「很奇怪、不符合视觉规律」。
- 纯人像全屏，以及在人像上加花字。
- 喧宾夺主的全屏大动效、花哨转场（旋转、翻页、闪白之类）。
- 录屏里的空列、空白区域、拖拽出错的部分。只挑每行每列都有数据的那一小段，不够长就定格最后一帧。
- 推近后把口播提到的按钮裁掉：先抽帧核对。

### 第 1 集的基线

- 画面切换：交叉淡化 0.3s，ease-out cubic。
- 录屏片段之间：硬切。
- 录屏镜头：固定，或快推后定住。快推在片段开始 0.5s 后用 0.6s smoothstep 推到目标框，推到位后画面不再移动。
- 取景框是 [x, y, w]，高度 = w × 765/1360，y + 高度不能超过原图高度。
- 动效基本件（anim/lib.js）：

| 名字 | 效果 |
|---|---|
| rise | 0.5s 从下 36–40px 上浮，模糊 10px 到 0，同时淡入 |
| popin | 0.45s 弹出（back 缓动） |
| wipe | 0.4s 从左往右刷出（色块、高亮） |
| grow | 横向长出 |
| dim | 已讲过的条目压暗到 0.25 |
| draw | SVG 描线 |
| typeText | 逐字打出，22 字/秒 |

### 可以做得更好的方向（每集挑一两个先做小样）

- **有关联的转场**：例如课件上的提示词框放大，直接变成录屏里的输入框；或者三张小卡里点中一张，放大成整条成品视频。用同一元素的位置变化代替淡化。
- **方向性推进**：同一章节内的下一步，内容从右往左推入，和步骤顺序一致。章节切换时，进度条填充滑到下一段，与画面切换同步。
- **录屏里的引导**：光标点击处出现涟漪，口播提到的按钮用描边框画出来，周围轻微压暗；文字较多时，对正在讲的那一行做高亮扫过。这些都叠在定住的画面上，画面本身不慢慢移动。
- **快推的质感**：推近时带一点运动模糊或缓动回弹，推到位后用描边框框住目标。
- **数据和结果的出现**：表格逐行出现、数字从 0 滚到目标值、成品视频从卡片里放大出来。
- **动效卡更有层次**：元素分前后景，轻微视差；关键词色块刷出后再落字。

### 新动效怎么上线

1. 先用真实口播做一段 10–15 秒的小样，和第 1 集的同一段并排给 du 看。
2. du 认可后再用到整片，并把它加进上面的基本件和第三节的版式库，写清楚适合什么文案。
3. du 否掉的写进「硬性不要」。

## 五、字幕和进度条【定死】

### 字幕

- 中文：得意黑 Smiley Sans 54px，白色。
- 英文：第二行，得意黑 30px，#E1E3E8。
- 底条：rgba(16,17,20,0.72)，圆角 16，水平居中。
- 每句显示到「下一句开始」和「本句结束 +0.25s」两者中较早的那个。
- 无动画；关键词不变色。

### 进度条

- 位置：x 64→1856，段间距 8，条高 8px，y=40，圆头。
- 颜色：底色 rgba(20,24,32,.09)，已播放填 #2F6BFF。
- 章节数不固定，按 chap_names.json 来（chap.json 的时间点数 = 章节数 + 1）；合成器和章节名图层都自动适配，rules.py 会检查两份表对得上。
- 每段宽度按章节时长比例分配。
- 章节名：MiSans 19px，y=58，左对齐段起点。当前章节 700 字重 #15171C，其他 500 字重 #9AA0AA。
- 章节名平铺，不编号、不加括号。第一段叫「效果展示」，不叫「开场」。
- 章节名图层必须和进度条用同一份章节时间表生成。第 1 集就踩过坑：两份时间表不一致，章节名和进度条错位了一整版。

## 六、PPT（课件页）样式【定死】

- 尺寸 1920×1080，HTML 写，Playwright 截图，再缩进左内容区。
- 底色 #FCFCFA，正文 #16181D，次要文字 #5A5F6B / #A0A4AE。
- 字体：思源黑 Noto Sans SC（500/700/900）。数字用 Archivo 800。
- 主色 #1E88E5（蓝），强调 #F06A1C（橙），浅蓝 #E3F1FD。
- 内边距约 128px。标题 72px / 900 字重；正文 30–34px。
- 页脚：「电商 + AI 系列 · 第 N 集」+ 页名，24px 灰。
- 讲稿写在 `<aside>` 里，样式里必须 `aside{display:none}`，否则讲稿会印到画面上。

### 页型

| 页型 | 样式 |
|---|---|
| 封面 cover | 系列名 + 两行大标题 + 一句副标题 |
| 目录 agenda | 两部分，每部分标题 + 时长（如「4 分钟」） |
| 章节页 d1 / d2 | 整页主色蓝底，左边 360px 大号「01 / 02」，右边章节名 120px 白字 + 一行小字说明，底部两段进度 |
| 步骤提示词页 s2a… | 顶部步骤进度块 1 2 3 4（当前步蓝底，写步骤名），标题「第 N 步：xxx」。中间黑底 #16181D 提示词框：橙色小标签「提示词 · 直接复制」，白字 30px 行高 1.6。底部一条橙色方块 + 一句提醒 |
| 回顾 recap | 「记住四步：拆解、策划、生成、管理」+ 四列，每列图标 + 步骤名 + 一行说明，底部一句行动建议 |
| 预告 next | 主色蓝底，「下集预告 · 第 N 集」+ 120px 标题 +「记得关注，我们下集见」 |

### 文案规则

- 课件上的提示词必须和录屏里实际输入的一字不差。录屏到了就按录屏改，不要留「待按录屏更新」。
- 步骤名全片统一，例如：拆解爆款视频 / 策划新脚本 / 生成视频并调优 / 打通飞书管素材。
- 编号要么全有要么全无：进度条不编号；步骤页和章节页编号。
- 删掉的功能（例如演示不了的画布），课件、目录、回顾、进度条要一起改。

## 七、口播剪辑

- 全片保留原声，不加 BGM（音效「待定」）。
- 删句：列出「保留区间」，接口加 12ms 音频淡化。可以从后面一句借一两个字接上（如借「咱们就」），人像小跳切是正常的。
- 删内容前，先把要删的原文和接上后的句子列给 du 确认；再试剪一小段给他听。
- 删减后，字幕时间按保留区间重新映射；错字逐条改。
- 云端下不了语音模型时，用 RMS 能量包络找字和字之间的切点。

## 八、合成流程

1. **素材盘点**：列出缺的素材，写清编号、成片时间点、要录哪几下。缺的先用占位往下剪。
2. **口播粗剪**：得到 src_cut.mp4 + 字幕 json（[开始, 结束, 中文]）+ 英文 txt（逐行对应）。
3. **写时间轴**：segs.json，每段 {t0, t1, layer, tag}，layer 写成 `类型:名字`，类型有：
   - slide 课件；
   - scene 标题卡 png；
   - anim 动效帧；
   - rec 单段录屏 + 关键帧缩放；
   - clips 多段录屏，每段 [lt0, lt1, 帧目录, 框0, 框1, 推近时刻]；
   - cmp 开场对比；
   - vid 成品展示。

   每段可加 `"trans": "cut"` 改成硬切（见第四节清单）。写完先跑 `python rules.py` 自检。

   另有 chap.json 记录章节起点（最后一个数是全片终点），chap_names.json 记录章节名，进度条和章节名图层都从这两份生成。
4. **出关键帧**：合成器支持只渲染 0.034s，抽单帧看。每处改动都出改前 / 改后对比图，放在同一个 Artifact 关键帧页里，每轮刷新同一个链接。du 确认后再合成整片。
5. **合成**：Python（numpy + cv2 + PIL）从 ffmpeg rawvideo 管道读口播帧，逐帧画「底图 → 左内容 → 人像 → 进度条 → 章节名 → 字幕」，再送进 libx264 crf19。全片切 4 段并行，`concat -c copy` 拼接，最后从 src_cut.mp4 mux 音频（aac 192k）。8.5 分钟约 12 分钟出片。只改了某一段时，只重渲那一段所在的分块。
6. **抽查**：至少看 9 个时间点：每种版式各一个，加上所有改过的地方，还要核对总时长。

## 九、交付

- 成片同时放两处：资料库「<课程>_成片/名称_vN.mp4」，以及 du 的桌面文件夹。
- 推到桌面的文件超过 25MB 时：
  1. 用 `ffmpeg -f segment -segment_time 75 -c copy` 切成多段，每段小于 25MB；
  2. 逐段推到桌面的 `_vNtmp/`；
  3. 在 du 的设备上用 ffmpeg concat 拼回完整文件，核对时长；
  4. 告诉 du 临时文件夹可以删。
- 线程附件满了就不要再发附件，改用关键帧 Artifact 页和资料库路径。

## 十、和 du 合作的规矩

- 先出关键帧，确认后再合成。改动要给「改前 / 改后」两张图并排，只有文字描述 du 看不懂。
- 关键帧一做好就先发，不要攒到最后。
- 给选项时做成小样，例如字体做拼图、动效做 15 秒小样视频。
- du 用语音输入，转写可能有错字（例如「回放、硅谷」其实是「回顾」）。按语义理解，并说明你是怎么理解的。素材文件名和内容对不上时，先看内容再配对。
- 一条消息里有多个要求时，逐条做完，并逐条回复对应的时间点。
- 连不上 du 的 Mac 时，直接弹授权 / 连接卡片，不要只发文字让 du 自己排查。
